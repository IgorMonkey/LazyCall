## Порядок работы

S1 и S2 закрывают главные технические риски до красивого UI. После них S3 даёт настоящий сквозной поток; S4 проверяет полезность; S5 — возможность пользоваться им вне dev-сервера.

### S1. Capture и синхронизация

**Цель:** доказать два независимых звуковых источника и автоматические кадры выбранного окна на этом компьютере.

Минимальный disposable Electron harness: выбор источников, два RMS-индикатора, счётчики PCM/gaps, preview и timestamps. Без LLM, оформления, истории проектов и постоянной записи raw audio/video.

Проверки:

- [ ] Микрофон отдельно: речь пользователя даёт сэмплы в self, выключенный микрофон/нет разрешения даёт понятный статус.
- [ ] Remote отдельно: тестовый звук в ВКС даёт сэмплы в loopback; есть реальный audio track и ненулевые данные.
- [ ] Одновременная речь сохраняется двумя потоками, роли не меняются.
- [ ] Zoom и Телемост испытаны отдельно с реальным удалённым участником или вторым устройством.
- [ ] Вывод ВКС совпадает и не совпадает с default output; явно записан фактический источник loopback.
- [ ] USB/Bluetooth: подключение, отключение, смена endpoint/profile. Если захват не восстановился, обнаружен gap и возможен перевыбор.
- [ ] Системное уведомление/другая музыка показывают фактический scope audio. Нельзя объявить window-only capture.
- [ ] Выбран правильный экран демонстрации; automatic change frames работают без ручного клика.
- [ ] Движение курсора/лица не вызывает неограниченную очередь; быстрый переход или меню проверены на пригодность кадра.
- [ ] Минимизация, перекрытие, закрытие и пересоздание окна, смена DPI/монитора дают проверенное поведение и screen-stale.
- [ ] Нагрузка UI и 20 минут работы не вызывают роста audio queue/memory; измерена синхронизация и drift.
- [ ] Stop немедленно выключает новые захваты. Не остаются собственные активные tracks.

Начальные критерии: нет необъяснённых gaps в обычном 20-минутном прогоне; очереди ограничены; ошибка источника обнаруживается не позднее 2 секунд; пригодный кадр после заметного изменения обычно появляется в пределах 2 секунд. Задержка capture↔utterance измерена, существенная неопределённость не скрыта.

**Выход:** таблица «ВКС × endpoint × режим окна», фактические sample rate/форматы, CPU/RAM, gaps, свежесть кадров и решение: Electron достаточно либо нужен native helper.

Если необходим произвольный output endpoint и Electron его не даёт, зафиксировать ограничение продукта либо выполнить отдельный helper spike. Не подменять это успешным тестом default speakers.

### S2. Codex: протокол, изоляция, capability

**Цель:** проверить отдельную сессию и безопасную поверхность реального выбранного runtime.

Сначала всё на синтетических fixtures в app-owned временном каталоге. Первая baseline-версия — установленный CLI 0.145.0. Не менять глобальную установку; если нужен более новый бинарник, использовать отдельную управляемую копию и новые схемы.

- [ ] Разрешение native executable не зависит от временного PowerShell/fnm shim, версия явно зарегистрирована.
- [ ] Отдельный CODEX_HOME и штатный login; конфиги текущего Codex, его MCP/плагины и история не импортируются.
- [ ] Handshake initialize/initialized, start thread, две последовательные реплики, корректный mapping IDs.
- [ ] Получена реальная текстовая delta до terminal turn; UI умеет сверять final snapshot.
- [ ] Синтетическое изображение читается моделью, выбранная модель действительно имеет image capability.
- [ ] outputSchema даёт валидный итог; отказ/обрыв/невалидный ответ обрабатываются как ошибка.
- [ ] Прерывание long turn завершает только этот turn; следующий вопрос запускается без смешения дельт.
- [ ] Research-thread и live-thread независимы; rate limit/latency при двух генерациях измерены.
- [ ] Нет скрытого произвольного shell, файловых инструментов, inherited hooks/apps/MCP. Допустимый набор инструментов перечислен и проверен для этой версии.
- [ ] Canary внутри разрешённого snapshot читается; harmless canary вне allowlist не читается ни прямым file tool, ни shell.
- [ ] Prompt injection в тексте/кадре fixture не расширяет доступ и не меняет output path.
- [ ] Запрос записи/запуска команды из встречи не меняет код и не вызывает внешних действий.
- [ ] Secrets/ключ STT не попадают в child env, argv, stderr, event log. Тестировать фальшивыми значениями.
- [ ] Проверено, что ephemeral и настройки логов делают с fixture-данными на диске; не объявлять абсолютную zero-retention.
- [ ] Остановка/падение child не затрагивает открытое приложение Codex и другие процессы пользователя.

**Условие допуска:** подтверждены text deltas, изображения, отмена, structured final и границы чтения. Одного read-only/cwd/prompt недостаточно. Если запрет чтения обеспечить нельзя, живой агент не допускается, пока не ограничены инструменты/OS-доступ. Никаких попыток читать реальные секреты ради теста.

Доступность штатного login и аккаунта потребует участия пользователя только когда начинается живой эксперимент. В рамках текущего аудита login не запускался.

### S3. STT и durable transcript

**Цель:** получить настоящий русский transcript двух источников, который сохраняется независимо от Codex.

Режим replay для разработки реализуется с постоянной плашкой. Первый живой STT-кандидат — встроенный Whisper / whisper.cpp, с поставляемой мультиязычной моделью. Сравнить medium и large-v3-turbo, при необходимости quantized variants. Soniox/Yandex — опциональный резерв после измерения локального режима; без отдельно предоставленного ключа/подключения платный тест не выполняется.

- [ ] Оба mono-streams реально распознаются одной загруженной локальной моделью с раздельными source windows; очередь не растёт при одновременной речи.
- [ ] PCM format/rate/channels соответствуют worker; overlap/VAD не обрезают окончания и не порождают повторы.
- [ ] CPU/GPU backend и выбранная модель отражены в UI; GPU load failure корректно переводит в проверенный CPU fallback.
- [ ] Для опционального облачного адаптера: современный WebSocket auth; ключ не передаётся в renderer или deprecated start-only схеме.
- [ ] Отдельно измерены partial latency, word-final latency и utterance close latency.
- [ ] Корпус минимум 10–15 минут русской речи: термины проекта, английские названия, числа/суммы, отрицания, перебивания, тишина.
- [ ] Ручная эталонная расшифровка позволяет посчитать WER на выбранном фрагменте; отдельно проверены смысловые ошибки требований.
- [ ] Final token не создаёт по одной заметке на слово; UtteranceAssembler корректно собирает мысль.
- [ ] Disconnect 5/30 секунд, повторные пакеты и reconnect не вызывают бесконечных дублей; gaps явно записаны.
- [ ] Отказ/задержка Codex не блокируют final→writer→ack.
- [ ] После Stop есть flush/timeout и нет выдуманного final из partial.
- [ ] Принудительный crash во время append восстанавливает валидный префикс; повреждение в середине видно.
- [ ] Ошибка/заполнение диска не оставляет UI показывать несохранённый final как сохранённый.

Предварительный latency target: final завершённой фразы p95 ≤3 секунд после её конца. WER фиксировать вместе с условиями; окончательный порог качества устанавливается по тому, сохраняются ли требования, числа и отрицания. Голосовые роли не превращаются в реальные имена.

**Выход:** выбранные базовая модель и backend, sample corpus с разрешёнными данными, latency/errors двух потоков, RAM/VRAM и минимальные требования. Для облачного сравнения дополнительно учесть billed units обоих потоков. Запуск на RTX 2080 Ti не заменяет измерения CPU/другой машины.

### S4. Полезность подсказок и журнала

**Цель:** пройти принятый полный флоу на сквозном прототипе.

- [ ] Как минимум 20 заранее подготовленных вопросов; достаточно повторов, чтобы оценка p95 не опиралась на 2–3 ответа.
- [ ] Измерены времена: конец вопроса → STT final → отправка agent → первая delta → первая полезная формулировка → verified supplement.
- [ ] Ориентир первой полезной формулировки p50 ≤5 секунд и p95 ≤10 секунд после готового вопроса. Если не достигнут — пересмотр provider/model/контекста/UX до заявления realtime.
- [ ] «Помоги ответить» работает без автоопределения; автоподсказки не запускаются на каждый partial.
- [ ] Новый вопрос не получает старую позднюю карточку; queue size и input budget ограничены.
- [ ] Длинное research не блокирует live-thread; проверенные источники и предположения различаются.
- [ ] Изменение экрана учитывается автоматически; старый/потерянный кадр маркируется.
- [ ] Пройдены сценарии «предложение без согласия», «отказ от предложения», «решение с условием», «неизвестный срок/ответственный».
- [ ] Задача ссылается на существующие реплики/кадр; предложенные критерии отделены от согласованных.
- [ ] Ручная правка не перезаписывается моделью; коррекция transcript помечает зависимые выводы.
- [ ] Stop → summary/backlog → локальный экспорт проходит; LLM failure оставляет transcript export.
- [ ] Переключение на fake второй provider проверяет независимость контракта без реализации нового платного API.

**Выход:** transcript и журнал одной репетиции, проверенные человеком summary/backlog, перечень ошибок и фактическая latency. Демо с заранее записанными ответами не считается прохождением живой проверки.

### S5. Упаковка и репетиция

- [ ] Приложение запускается без Vite dev server и установленного системного Node для UI/runtime Electron.
- [ ] Полный installer содержит Whisper worker, базовую модель, runtime-библиотеки и notices. Первый локальный transcript работает без сети и без ручной установки Python/Whisper/toolchain.
- [ ] Запуск на другом поддерживаемом Windows-ПК/чистом пользовательском профиле не использует пути, DLL, model cache и CLI разработчика.
- [ ] CPU режим без NVIDIA проверен отдельно; заявленный GPU backend проверен на соответствующих устройствах. При недостаточной скорости UI показывает отставание/лёгкий профиль.
- [ ] Codex runtime поставляется приложением и находится без глобального codex/Node; штатный вход выполняется через UI/управляемый процесс.
- [ ] Внутри actual main/utility записаны process.versions и подтверждён набор используемых Node APIs.
- [ ] Async safeStorage работает в упакованном Windows приложении; plaintext fallback отсутствует.
- [ ] IPC origin/schema/size validation действует в production build, external links не открывают произвольные схемы.
- [ ] Codex runtime найден после перезагрузки системы; неизвестная версия даёт явную ошибку.
- [ ] Нет orphan app-owned процессов после Stop/Exit; чужие процессы не затронуты.
- [ ] Повторены mic/system/window capture и запись журнала в packaged build.
- [ ] Проведена реальная репетиция отдельно в Zoom и в Яндекс Телемосте.
- [ ] Измерены RAM/CPU, размер поставки, места хранения и восстановление после crash.
- [ ] Инструкция первого запуска отражает встроенную модель, фактический CPU/GPU режим, отдельный Codex login, audio scope и retention; STT key нужен только облачной опции.

26 октября 2026 подготовлен пошаговый per-user NSIS-установщик 0.3.0 без автообновлений. Упакованное приложение прошло изолированную проверку, а вариант установщика с уникальными EXE/GUID — реальную установку и удаление в собственной временной папке. Публичная подпись, проверка другого компьютера и живые репетиции ВКС остаются отдельными проверками. Неподписанная локальная сборка и подписанная распространяемая программа — разные уровни готовности.

## Оценка работ

Оценки — инженерные диапазоны, не обещания календарной готовности.

| Этап | Ориентир |
| --- | --- |
| Capture + Codex isolation/protocol spikes S1/S2 | 3–6 часов |
| Тонкий сквозной prototype, включая S3 | 10–18 часов суммарно |
| Полезный личный вариант с журналом, восстановлением и обеими репетициями | 20–36 часов суммарно, обычно 3–5 рабочих дней |

Ранее обсуждавшиеся 16–28 часов остаются оптимистичным путём при готовом STT и успешном capture. Аудит добавил явные расходы на app-server lifecycle, границы чтения и recovery. Уточнённая автономная поставка Whisper/модели/Codex и проверка на другом компьютере требуют уточнения оценки после S3/S5; диапазон выше не гарантирует готовый универсальный installer. Native helper, проблемы Windows-изоляции, несовместимый GPU runtime, недоступный аккаунт или неудовлетворительная latency требуют отдельной переоценки.

## Критерий первого полезного варианта

Полный флоу пройден в обеих ВКС: два живых аудиоисточника, автоматические кадры, короткие подсказки, независимый durable transcript, редактируемый журнал, честные решения/предложения, Stop и восстанавливаемый локальный экспорт. Все временные ограничения видны пользователю. Будущие LLM-адаптеры, внешний task tracker и изменение кода для этого не требуются.
