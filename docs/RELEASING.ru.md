# Выпуск LazyCall

[English](RELEASING.md)

Это процедура ревью, а не публикации. Текущий кандидат — `v0.3.5-alpha.1`; он остаётся pre-release, пока мейнтейнер явно не проверит артефакты и не опубликует его.

## Перед запуском workflow

1. Используйте чистый проверенный коммит в `main` и задайте в `package.json` точную semver pre-release версию, например `0.3.5-alpha.1`.
2. Создайте тег `v0.3.5-alpha.1` на этом же коммите. Ручной workflow отклонит тег, который не равен `v` плюс версия из package, или указывает на другой коммит.
3. Проверьте публичную границу данных: в скриншотах и тестовых доказательствах используйте синтетические расшифровки и имена проектов. Не кладите в артефакты или release notes настоящие встречи, закрытый код, учётные данные или данные пользователя.
4. Оставьте существующие имя и иконку LazyCall. Не добавляйте непроверенный логотип или ребрендинг при подготовке выпуска.

## Подготовка артефактов для ревью

Запустите **Prepare release review artifacts** с двумя явными входами:

- `tag`: `v0.3.5-alpha.1`
- `ref`: SHA коммита с тегом или сам тег

Windows workflow получает этот ref, проверяет тег и версию package, выполняет `npm ci`, build и tests, загружает закреплённый локальный speech runtime и создаёт лёгкий public stage. `CALLME_RELEASE_REPOSITORY` задаётся как `github.repository` до staging, поэтому упакованное приложение использует проверенную identity репозитория.

Затем workflow запускает packaged public-light smoke, собирает web-установщик и полный установщик как артефакты ревью, пишет `SHA256SUMS.txt` и загружает Actions artifact на 14 дней. У workflow только read-only доступ к репозиторию. Он не создаёт GitHub Release, не загружает release assets, не публикует пакет и не включает обновления.

## Alpha update feed

Если до public staging задано `CALLME_RELEASE_REPOSITORY=IgorMonkey/LazyCall`, stage записывает GitHub-provider feed для точных owner и repository. Приложение разрешает поиск prerelease, когда его собственная semver-версия содержит суффикс prerelease, поэтому `0.3.5-alpha.1` использует соответствующий feed `alpha.yml`. Для опубликованного обновления нужны полный NSIS-установщик и соответствующий `alpha.yml`; не публикуйте их, пока установщик и обновление не прошли настоящую end-to-end проверку.

## Ручной gate выпуска

Скачайте Actions artifact и проверьте имена установщиков, SHA-256 sums, manifest public stage, отчёт packaged smoke и скриншоты. Убедитесь, что preview-метка видна там, где пользователь увидит артефакт, и что в тестовых доказательствах нет приватных данных встречи или проекта.

Перед публикацией проверьте скачивание на чистой Windows x64: успешную установку, ошибку checksum, скачивание и установку Microsoft VC Runtime, onboarding без Codex, onboarding с установленным Codex, удаление и обновление с предыдущей совместимой сборки. Прочитайте потоки данных в [PRIVACY.ru.md](PRIVACY.ru.md) и release notes. Онлайн-установщик и автообновления не готовы к публичной раздаче, пока эти проверки не записаны и мейнтейнер явно не опубликует ассеты.

## Ревью настроек репозитория

[`.github/repository-settings.json`](../.github/repository-settings.json) — ручной план настроек: для `main` требуется Windows CI, force push и удаление запрещены, а обязательное число approvals не задано для проекта с одним мейнтейнером. Применяйте его в GitHub только после ревью: сам файл не меняет настройки GitHub.
