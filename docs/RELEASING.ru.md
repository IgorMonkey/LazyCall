# Выпуск LazyCall

[English](RELEASING.md) · [GitHub Flow и версии](DEVELOPMENT_WORKFLOW.ru.md)

Мейнтейнер выбирает и публикует релизы. Workflow готовит артефакты с доступом только на чтение: он не публикует релиз и не сливает PR автоматически.

## Подготовить кандидата

1. Используйте проверенный чистый коммит в `main`. Задайте точную SemVer-версию в `package.json`; при необходимости обновите `yarn.lock` через `yarn install`. Выполните `yarn install --immutable`, `yarn build`, `yarn test` и проверки затронутых UI и packaged-сценариев. Windows CI должен пройти.
2. Соберите публичные артефакты с правильным GitHub feed по [BUILD.ru.md](BUILD.ru.md). В них нет встроенного Codex и app-local DLL Microsoft VC: при необходимости установщик предлагает официальный компонент Microsoft.
3. Используйте синтетические встречи и проекты на скриншотах. Проверьте артефакты и логи на приватные данные, секреты и локальные пути.
4. Создайте аннотированный тег `v<версия>` на этом коммите. Опубликованные теги не передвигают, ассеты не заменяют.

Workflow **Prepare release review artifacts** принимает тег и точный commit/ref, проверяет их соответствие, использует закреплённый Yarn, выполняет проверки, собирает public stage и оба установщика. Артефакты хранятся 14 дней; прав на публикацию у workflow нет.

## Опубликовать черновик

Создайте draft GitHub Release. Обычная версия вроде `0.3.5` публикуется без prerelease-флага; этот флаг нужен только для версии с намеренно выбранным суффиксом. Загрузите ассеты с точными именами; для `0.3.5` это:

- `LazyCall-Web-Setup-0.3.5.exe` — небольшой загрузчик.
- `LazyCall-Setup-0.3.5.exe` — полный установщик.
- `lazycall-0.3.5-x64.nsis.7z` — пакет для загрузчика.
- `latest.yml` — метаданные обновления полного установщика.
- `SHA256SUMS.txt` — контрольные суммы с этими же именами файлов.

Сверьте URL пакета в загрузчике, закреплённый хэш, SHA-512 полного установщика в `latest.yml`, все SHA-256, размеры ассетов и коммит тега. Завершите загрузку в черновик. После ревью публикуйте релиз: immutable releases блокируют изменение тега и ассетов после публикации.

## Проверки и ограничения

Проверьте изолированные установку, запуск, сетевую ошибку, повреждённый пакет, повтор и удаление. Ошибка должна сохранять существующую установку. Проверьте онбординг с найденным Codex и без него. Перед обновлением проверьте совместимость данных; установка во время записи запрещена.

Для первого публичного релиза локально проверены эти сценарии установщика и работа packaged-приложения. Чистая Windows без Microsoft VC Runtime и настоящее обновление с предыдущего публичного релиза ещё не проверены. Драйвер обновлений и GitHub-provider проверены локальными fixture; установка обновления из опубликованного GitHub-релиза остаётся непроверенной. Укажите эти ограничения и отсутствие подписи в release notes. Для широкого рабочего использования нужны проверки на чистой машине и настоящее обновление.

## Настройки репозитория

[repository-settings.json](../.github/repository-settings.json) описывает нужные настройки, но сам их не применяет. Проверьте в GitHub обязательные PR и Windows CI для `main`, запрет force push и удаления, squash merge, отключённое автослияние, приватные сообщения об уязвимостях и immutable releases. Какие PR сливать и какие кандидаты выпускать, решает мейнтейнер.

## Статистика загрузок и репозитория

Команда `node scripts/release-stats.cjs` через авторизованный GitHub CLI показывает счётчики опубликованных установщиков. Добавьте `--traffic` для посещений и клонирований репозитория (нужен push-доступ, окно последних 14 дней) либо `--json` для машиночитаемого снимка. Для локальной истории сохраняйте JSON в игнорируемой папке `test-results/`. При необходимости запускайте команду самостоятельно; расписание и телеметрия приложения не включены.

Загрузчик, полный установщик и web-пакет показаны отдельными строками. Загрузки загрузчика и пакета нельзя складывать как число пользователей. Повторные скачивания и обновления влияют на счётчики; по ним нельзя узнать завершённые установки, активных пользователей или удержание. Команда читает только агрегаты GitHub и не обращается к работающему LazyCall.
